What it does

Everything a production bench actually needs

Not a wrapper around one esptool call — a full workflow for configuring, validating, flashing, and auditing a bench of boards.

True parallel flashing

Every device you upload to gets its own worker thread and its own esptool subprocess. A slow or stuck board never blocks the others, and the UI never freezes.

Automatic firmware detection

Point the app at a build output folder. It recognizes bootloader.bin, partition-table.bin, firmware.bin and assigns standard flash addresses automatically.

Project files (.efmproj)

Save a whole bench — every device, firmware path, flash setting, and window layout — to one JSON file. Missing firmware on reopen is flagged, not a crash.

Pre-upload validation

Duplicate ports, missing firmware, invalid or overlapping addresses, and bad chip selections are caught before a single byte is written — errors block the upload.

Flash history + CSV export

Every attempt — success, failure, or cancellation — is logged with device, firmware, date, and duration, exportable for QA and traceability records.

Flash Encryption & Secure Boot

Generate or import keys and burn eFuses through espsecure/espefuse — gated behind an acknowledgement box and a typed confirmation phrase.

Merge Bins

Combine a device's separate firmware images into one flashable .bin entirely offline, with pre-merge validation for missing files and overlapping regions.

Built-in Serial Monitor

Open any number of ports at once, each in its own window, with baud selection, auto-scroll, search, and save-to-file — no extra tool required.

Interface Lock

Hand a bench to an operator with Settings Lock (uploads stay usable, configuration doesn't) or Full Lock — both behind a SHA-256-hashed key.

How it works

One click, N independent flashes

The app never talks to a chip directly — it drives Espressif's own esptool as a subprocess per device, which is how correctness is preserved while still scaling to any bench size.

You click Upload

One action, applied to every device you've configured on the bench.

N worker threads

Each device gets its own thread and its own esptool subprocess — nothing is shared or serialized.

N boards, live

Progress, logs, and result land per device in real time — a stuck board never blocks the rest of the bench.

Why not just Espressif's tool

Not another Flash Download Tool clone

Espressif's own Flash Download Tool is the closest official equivalent, and both tools flash real hardware correctly — the difference is workflow, platform reach, and how far past "flash one image" each one goes.

Get running

From clone to your first flash in four steps

Runs identically on Windows, macOS, and Linux — there's no platform-specific setup step.

  1. Clone the repository

    Get the source and step into the project directory.

  2. Create a virtual environment

    Keeps dependencies isolated from the rest of your system.

  3. Install dependencies

    pip install -r requirements.txt pulls in PySide6 and esptool.

  4. Run the app

    Or grab a packaged installer/portable build from the Releases page instead.

bash 
# 1. Clone this repository and set up a virtual environment
git clone https://github.com/SomangshuDas/esp32-multi-flash-manager.git
cd esp32-multi-flash-manager
python -m venv .venv

# macOS / Linux
source .venv/bin/activate

# Windows
.venv\Scripts\activate

# 2. Install dependencies and run
pip install -r requirements.txt
python run.py

Questions

Frequently asked

Is this affiliated with Espressif?
No. It's an independent open-source project that drives Espressif's own esptool, espsecure, and espefuse as subprocesses — the flashing protocol itself is never reimplemented, so correctness comes from the same tools Espressif's own Flash Download Tool relies on.
Is it free to use?
Yes. It's MIT licensed and the source is fully available on GitHub. esptool/espsecure/espefuse remain separate GPLv2 dependencies.
How many devices can I flash at once?
There's no hard-coded limit — every device gets its own thread and its own esptool subprocess. In practice the ceiling is your USB hubs and host machine, not the app.
How well-tested is each platform?
Windows 10 is tested. Linux and macOS installers are not yet tested on real hardware by the maintainer (no Apple hardware available), though the app itself runs identically on all three. If you hit an issue on Linux or macOS, reports are welcome.
Where do I report a bug or request a feature?
Open an issue on GitHub Issues. See CONTRIBUTING.md if you'd like to submit a fix yourself.

An example project is included — open it and start clicking

examples/example_project.efmproj ships with dummy firmware sized like real ESP-IDF output, so you can explore the whole UI before you ever touch real hardware.
